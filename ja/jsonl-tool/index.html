JSONL 検証・JSON 変換

JSONL の構文を検証して JSON 配列と変換します。大きな数の表記を維持し、重複キーや構文エラーの位置を確認してブラウザー内で保存します。

JSONL入力

入力はUTF-16で20万単位・UTF-8で1,000,000バイト以内、深さ100・値の合計20,000個以内です。JSONLは出力配列1個を含めて数えます。出力は2MiB以内です。

1行にJSON値を1個入力してください。空行・BOM・重複キーは拒否し、末尾の改行1個は許可します。大きな整数・小数・指数の数値表記は保持しますが、文字列のエスケープや書式は整理される場合があります。スキーマや業務上の正しさを保証する検証ではありません。

入力と結果はブラウザーのメモリ内だけに置き、再読み込み・移動時に消去します。内容やファイル名を分析・URLに送りません。保存したファイルは端末に残ります。

公開サンプルをそのまま実行するか内容を編集してください。

使い方と例

公開 JSONL 例は id が 9007199254740993 の Alpha と id が 2 の Beta の二行です。検証で 2 レコードを確認し、配列変換でも長い数値を維持します。JSONL は物理的な一行に JSON 値を一つ置きます。配列・文字列・数値・真偽値・null も使えますが、空行と BOM は拒否します。JSON 配列からは各要素を JSONL の一行として出力します。

よくある質問

大きな数と小数の表記は保たれますか？

9007199254740993・-0・1.2300・1e400 などの数値トークンをそのまま出力します。文字列値とキー順も維持しますが、空白や文字列エスケープの表記は正規化される場合があります。文書全体を JavaScript の数値に変換しません。

構文が正しければデータも正しいですか？

いいえ。スキーマや業務ルールは検証しません。互換性の曖昧さを避けるため、すべての深さでオブジェクトの重複キーを拒否します。エラーの行と列は 1 から始まり、列は UTF-16 コード単位です。

空の配列と処理上限は？

空の JSONL は拒否しますが、[] は 0 レコードの空 JSONL に変換します。入力は UTF-16 200,000 単位、UTF-8 1,000,000 バイト、深さ 100、全構造値 20,000 個までです。JSONL は出力配列の値一つを確保するため、スカラーは最大 19,999 個です。出力は 2MiB 以下です。

計算基準と参考資料

  • JSON Lines — Format

    UTF-8・行ごとの JSON 値・BOM 除外という JSON Lines 形式の根拠です。このツールはさらに重複キーを拒否します。

  • IETF RFC 8259 — JSONデータ形式

    JSON文字列・オブジェクト・エスケープ表記の基準です。変数名と一度の置換規則はこのツールで別途定義します。
