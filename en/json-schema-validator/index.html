JSON Schema validator

Check in your browser whether JSON follows a Draft 2020-12 schema’s type, required-field, range, and pattern rules. Values are not uploaded and external references are not fetched.

Usage examples and processing criteria

The example schema requires name to be a non-empty string and age to be an integer of 0 or greater. {"name":"Mina","age":28} passes both rules. Change age to a negative number or string to see the first failing keyword. The report omits JSON paths that could expose input values or object keys.

Frequently Asked Questions

Which JSON Schema version is supported?

Uses the Core and Validation keywords from JSON Schema Draft 2020-12. $ref and $dynamicRef resolve only local references beginning with # in the supplied schema; no URLs are requested. Other drafts and custom vocabularies are unsupported.

Does it validate format: email or date?

No. In Draft 2020-12, format is an annotation by default. This page disables format assertions, so it does not check email deliverability or whether a date is valid for a business purpose.

What are the input, number, and time limits?

Each schema and instance is limited to 100,000 characters, depth 100, and 20,000 values. Duplicate keys and integers outside JavaScript’s safe range are rejected. JSON numbers use JavaScript floating-point semantics, and the worker stops validation after 2 seconds.

Does the error report include input values?

Input values, data, object keys, and JSON paths are not included in reports or analytics. Only the first issue’s schema keyword is shown. Validation runs in your browser; inputs are not stored or sent.
