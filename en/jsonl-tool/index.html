JSONL validator and converter

Validate JSONL and convert JSON arrays without rounding large numbers. Detect duplicate keys, locate syntax errors and download results locally.

JSONL input

Input: at most 200,000 UTF-16 units, 1,000,000 UTF-8 bytes, depth 100 and 20,000 total values. JSONL counts one enclosing output array. Output: at most 2MiB.

Enter 1 JSON value per 1 line. Blank lines, BOM and duplicate object keys are rejected; 1 final newline is allowed. Numeric spellings, including large integers, decimals and exponents, are preserved. String escapes and formatting may be normalized. Validation does not establish schema or business correctness.

Inputs and results stay in browser memory and clear on reload or navigation. Contents and names are excluded from analytics and URLs. Downloaded files remain on your device.

Instructions and example

The public JSONL example has two lines: Alpha with id 9007199254740993 and Beta with id 2. Validation reports 2 records, and array conversion retains the long number. JSONL requires one JSON value per physical line. Arrays, strings, numbers, booleans and null are valid; blank lines and BOM are rejected. JSON array conversion emits each element as a JSONL line.

Frequently asked questions

Are large numbers and decimal spellings preserved?

Numeric tokens such as 9007199254740993, -0, 1.2300 and 1e400 are emitted unchanged. String values and key order remain, while whitespace and string escape spellings may be normalized. Whole documents are not converted through JavaScript numbers.

Does valid syntax mean the data is correct?

No. Schema and business rules are not checked. Duplicate object keys are rejected at every depth to avoid interoperability ambiguity. Error lines and columns start at 1; columns use UTF-16 code units.

How are empty arrays and limits handled?

Empty JSONL is rejected, but [] converts to empty JSONL with 0 records. Input limits are 200,000 UTF-16 units, 1,000,000 UTF-8 bytes, depth 100 and 20,000 structural values overall. JSONL reserves one value for the output array, allowing at most 19,999 scalar records. Output is at most 2MiB.

Calculation criteria and reference materials

  • JSON Lines — Format

    Defines UTF-8, one JSON value per line and no BOM. This tool additionally rejects duplicate keys.

  • IETF RFC 8259 — JSON Data Format

    Reference for JSON strings, objects and escapes. Variable names and one-pass substitution are separately defined by this tool.
