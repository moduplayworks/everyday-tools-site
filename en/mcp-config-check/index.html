Supported syntax and processing

Inspect key JSON shapes in Claude Desktop local stdio settings or required envelope metadata in MCP 2026-07-28 requests in your browser. The tool does not run commands, install packages, connect to servers or transmit secret values.

Claude Desktop settings mode checks command/args/env shapes under mcpServers and Windows path escaping. MCP 2026-07-28 request mode checks selected JSON-RPC 2.0 request fields, the protocol version and clientCapabilities shape in params._meta, and flags removed initialization-handshake methods. The public example is a tools/list request for the current revision.

Input example

The Claude Desktop settings mode starts with one local server, one args string and one env string value. Switching to MCP 2026-07-28 request mode loads a tools/list example shaped like the official specification and checks protocolVersion and clientCapabilities in params._meta. The example is not sent to a server.

Supported range and boundaries

Input is limited to 50,000 JSON characters. Settings mode allows 1–50 servers, 2,048-character commands, up to 200 args of 2,048 characters each, and up to 100 env values of 8,192 characters. Request mode checks only the JSON-RPC envelope and selected required metadata for the current revision, not full method schemas. It does not check HTTP MCP-Protocol-Version header/body agreement, connectivity, server responses, authentication, command execution or safety. Input values are not repeated in the result.

Inputs and results stay in your browser. They are not saved or put in URLs or analytics. Leaving or refreshing the page restores the public example.

Frequently asked questions

Does this check VS Code or Cursor settings?

Claude Desktop settings mode supports only the basic local stdio mcpServers format. Request mode checks the common envelope for MCP 2026-07-28; it does not check other clients' local settings-file formats.

What does the MCP 2026 request check inspect?

It checks the basic JSON-RPC 2.0 request shape and the current protocolVersion and clientCapabilities object in params._meta. It flags initialize and notifications/initialized as older handshake methods. It does not check full method schemas or whether a server supports every version.

Does a matching required field mean the connection will work?

No. This check only inspects the static request body you pasted. It does not check HTTP version-header agreement, transport, authentication, method-specific schemas or server responses; settings mode does not execute commands either.

Are secret values repeated in the result?

The result does not repeat server names, commands, environment values, request IDs, methods or metadata. Processing stays in the browser; input is not stored or sent to analytics or URLs.
