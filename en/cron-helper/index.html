Usage examples and processing criteria

Choose 9:30 AM on weekdays to generate the cron expression 30 9 * * 1-5. Its fields are minute, hour, day of month, month, and day of week. The next five run times are shown in this device’s time zone. If the server uses a different time zone, actual run times will differ.

Frequently Asked Questions

Do all cloud Cron expressions work?

No. It is the five field format of Cronie/Vixie users’ crontab. Some cloud task schedulers and Quartz have different number of fields, seconds, and day rules. Check the service documentation used before input.

Is the next execution example the same time on the server?

The example is calculated based on the local time zone of the browser device. The time matches only when it is the same as the cron daemon time. Cronie skips the local time when summer time does not exist and can run twice for recurring local times. Check the service documentation for other implementations.

If I select the 31st of each month, when is it executed in February?

If there are no 31 days in the month, it does not run. Dates are not automatically moved to the end of the month. If execution is required at the end of each month, check the syntax of the cron implementation or the calculation method for the next month.

Like 7 minutes – can it create any interval?

The interval provides a constant cycle divided by 60. Cron step values repeat within the field, so */7 counts from zero each hour, making the actual duration never exactly 7 minutes. Use a scheduler that supports a separate execution interval if a consistent time interval is required.

Will the generated cron job run if installed as is?

No. This tool generates only five fields representing execution times, so additional commands are required. The /etc/crontab and /etc/cron.d formats also require a username field.
